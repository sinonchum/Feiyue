Hermes Agent Console

Recommended architecture

The browser should talk to a Feiyue backend, not directly to Hermes credentials or provider APIs. A future Hermes Bridge sidecar can stream redacted session events here.

  1. Operator reviews evidence in Feiyue.
  2. UI submits an intent draft or creates a session draft.
  3. Backend checks policy and approval gates.
  4. G-3 emits provider-free simulated Bridge events.
  5. Operator creates exact approval gate via POST /api/hermes-session-drafts/:id/approve-dry-run.
  6. G-4 emits approval events; draft status transitions to approved_dry_run.
  7. G-5 cross-checks verifier evidence: event stream consistency, verification checks, and boundary preservation across every approval gate.
  8. G-6 pre-fills session draft fields from review inbox items via templates.
  9. G-7 replays approval events as execution output for approved dry-run drafts (two-phase: draft → approval → execute-no-provider).
  10. Real Hermes session still requires a second exact human approval gate.
